# 撤下与更正流程

本站收录的是**公开内容**，但公开不等于当事人愿意被收录。任何人（尤其是被提及的医生与机构）都可以要求撤下或更正。

## 1. 怎么提

通过 GitHub Issue 提交（需要 GitHub 账号，内容公开可见）：

| 类型 | 入口 | 适用 |
| --- | --- | --- |
| 撤下 | [`takedown.yml`](../.github/ISSUE_TEMPLATE/takedown.yml) | 我是当事人，要求下线某条记录 |
| 更正 | [`correction.yml`](../.github/ISSUE_TEMPLATE/correction.yml) | 记录中的事实、编码或机构信息有误 |
| 补充线索 | [`lead.yml`](../.github/ISSUE_TEMPLATE/lead.yml) | 提交新的公开来源 |

如果涉及隐私、不适合公开讨论，请在 Issue 中<strong>只写记录编号</strong>并说明「原因不便公开」，我们会通过 Issue 私密沟通渠道跟进，你无需在公开区透露个人信息。

## 2. 我们会怎么处理

| 请求类型 | 处理方式 | 目标时限 |
| --- | --- | --- |
| 当事人要求撤下自述线索 | 该条 `status` 改为 `withheld`：保留记录编号，内容与摘录下线 | 7 天内 |
| 机构/医生要求撤下评价类线索 | 同上；机构客观信息（名称、科室）如来自官方来源则保留 | 7 天内 |
| 事实性更正（编码、机构信息、摘录与原文不符） | 核实后修正，并在 Issue 中回复处理结果 | 7 天内 |
| 涉及未成年人、自伤细节、隐私泄露 | **立即下线**，无需论证 | 24 小时内 |
| 法律函件 | 先下线争议内容，再与提出方核实 | 收到即下线 |

## 3. 数据留痕规则

撤下不等于抹除历史。为保持数据可审计：

- `data/curated/reports.json` 中该条记录**保留** `id`、`platform`、`verification`、`status: "withheld"`。
- **删除**：`evidence_quote`、地区字段、医院/医生关联字段等一切可识别内容（本站本就不记录用户名与 IP）。
- `data/runs/` 中的运行日志保留（只含 id、平台、时间与来源 URL，不含内容）。
- 若要求连 id 一并移除，请说明理由，我们会从数据集中彻底删除该条编号。

## 4. 我们不会做的事

- 不会因为撤下请求而要求你提供身份证明（除非涉及明确的法律程序）。
- 不会公开撤下请求人的身份信息。
- 不会「先拒绝、再拖延」：任何隐私相关的撤下请求都先下线再讨论。

## 5. 反滥用

如果同一来源反复以撤下为名要求删除**批评性但真实**的公开内容，我们会回复说明依据与来源链接；
但**涉及个人隐私与未成年人**的请求不受此限，一律优先下线。
