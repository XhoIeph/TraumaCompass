# 证据规范（Evidence standards）

> 本文件是**强制规范**，不是建议。`npm run data:validate` 会按这里的规则拦截不合格数据，
> 不合格的数据不允许构建、不允许发布。
>
> 立规缘由（2026-09-11 事故）：首轮采集中出现三类失真 ——
> ① 把「全国DBT基地名单」当成一家医院登记；
> ② 原文没写地区却凭空指定省市；
> ③ 评论被 200 字上限截断、且丢掉父评论，导致「这个 / 它 / 楼上」没有指代对象。
> 这三类问题都是**摘录时忽略上下文**造成的。

## 1. 摘录三原则

| 原则 | 要求 |
| --- | --- |
| **逐字** | `evidence_quote` 必须与原文完全一致，不得改写、概括、拼接、补字。 |
| **完整** | 摘录不得因长度限制而丢失语义。原文超过 200 字时，`evidence_quote` 取关键句，**同时必须**把原文完整片段写入 `evidence_full_text`（≤2000 字）。 |
| **带上下文** | 摘录必须能被独立读懂；做不到就必须显式声明缺失（见 §4）。 |

## 2. 评论来源的额外要求（最容易出错的地方）

评论是**对话的一部分**，不是独立陈述。凡 `evidence_source: "comment"` 的线索，必须提供
`evidence_context`，且其中**至少一项**为真：

- `note_title`：这条评论出现在哪个帖子下（读者需要知道讨论背景）；
- `parent_excerpt`：若为回复，父评论的摘录（回答「这个 / 它 / 楼上」指什么）；
- `is_reply`：明确标注这是顶层评论还是楼中楼回复。

建议同时记录（可选）：`parent_author`、`reply_to_author`、`index_in_capture`（第几条/共抓到几条）、
`capture_scope`（原始抓取文件）。

**禁止的做法**

- ❌ 把楼中楼回复当独立陈述入库（例：「这个去郑大一附院看就OK了」——「这个」指楼上提问）；
- ❌ 只记录"抓取位置"就当作上下文（`index_in_capture` 是出处，不是上下文）；
- ❌ 评论区没抓全却假装完整 —— 必须写明抓取范围（例：「共 376 条，本次抓到 111 条」）。

## 3. 机构与地区：只写原文能支撑的内容

- **原文未点名的机构不得建立机构条目**。只能写入线索的 `hospital_name_raw`（并注明「原文未点名」），
  不得创建 `hospitals.json` 条目，更不得挂到地图上。
  校验规则：机构名匹配 `未点名|名单|线索|待核实|某精神|某脑科|某顶级` 的内容禁止关联 `hospital_id`。
- **名单、汇总帖、联盟名单不是机构**。它们是来源文档，只能作为线索来源或证据归档，不能建成机构。
- **地区不得臆测**。原文没有地区线索时，`hospital_region` / `self_reported_region` / `ip_location`
  一律留空。三者含义必须分清：
  - `hospital_region`：医院所在地；
  - `self_reported_region`：作者自述所在地；
  - `ip_location`：平台显示的 IP 属地（**不等于**居住地，也不等于就诊地）。

## 4. 上下文缺失怎么办

做不到 §2 时**不允许含糊过去**，必须二选一：

1. 补齐上下文；或
2. 显式写 `context_incomplete: true`，并在 `verification.notes` 说明缺什么、为什么缺。

站点会在卡片上打「上下文不完整」标记，并提示读者以原帖为准。**标记不是免罪符**：
列入补抓清单，带父评论重新抓取后应尽快消除。

## 5. 机器强制规则（`npm run data:validate`）

| 规则 | 违反后果 |
| --- | --- |
| 已发布线索必须有 `source_url` + `evidence_quote` | 构建失败 |
| `contains_minor` / `contains_selfharm_detail` 为真 → 不得 `published` | 构建失败 |
| 评论来源必须满足 §2（有意义上下文或 `context_incomplete`） | 构建失败 |
| 占位名不得关联 `hospital_id` | 构建失败 |
| `hospital_id` / `doctor_id` 必须存在 | 构建失败 |
| 机构 `adcode` 必须在 `provinces.json` 中 | 构建失败 |
| 机构无官方来源 | 仅提醒（站点显示「暂无官方来源」） |

## 6. 采集侧要求（对应 `scripts/collect/js/`）

- 评论抽取脚本**必须**捕获：是否楼中楼、父评论作者、父评论摘录、回复对象；
- 抓取范围必须落盘（抓到多少条 / DOM 里多少条 / 页面上共多少条）；
- 失败必须熔断：连续 3 次失败立即停止并写 `COLLECTION_HALTED.json`，禁止无人值守连打；
- 原始输出先落盘再解析，**stderr 也要落盘**（2026-09-11 因 stderr 未落盘，丢失了平台风控提示原文）。

## 7. 复核清单（每次入库前自问）

1. 这句摘录脱离原帖还读得懂吗？读不懂 → 补上下文或标记缺失。
2. 这是我改写的还是原文？有没有为了通顺而动过字？
3. 这条评论在回复谁？父评论我抓到了吗？
4. 机构名是原文写的，还是我推断的？推断的一律不建条目。
5. 地区字段依据是原文哪一句？找不到依据就留空。
6. 原文超过 200 字吗？超过了，`evidence_full_text` 存了吗？
