## 项目与启动

- 仓库：`XhoIeph/TraumaCompass`；Next.js App Router、React、Leaflet、GSAP，静态导出到 `out/`，main 通过 GitHub Actions 部署到 GitHub Pages。
- 使用 Node.js **24**。脚本直接运行 TypeScript；不要根据 package.json 的宽松下限选择旧运行时。
- 安装：`npm ci`。
- 检查：`npm run data:validate`、`npm run typecheck`、`npm run build`。build 的 prebuild 会校验数据并更新聚合；先完成一次 build，再单独运行 typecheck 可避免缺少生成的 Next.js 类型。
- 开发：`npm run dev -- --hostname 0.0.0.0 --port 3000`。服务保持运行后，使用云端提供的预览入口（如可用）；不要假定手机 localhost 指向云端。
- `public/geo/china-provinces.json` 已入库，普通开发无需重新抓取地图边界或地理编码。
- 本地开发不用设置 `GITHUB_PAGES=true`；它只用于 GitHub Pages 子路径构建。

## 密钥与迁移边界

- `NEXT_PUBLIC_TIANDITU_KEY`：可选的浏览器底图 key。不配置时用省界矢量回退，不是地图加载失败。若需要标准底图，在 Cloud 环境变量里单独设置，不能把 `.env.local` 提交。`NEXT_PUBLIC_` 值会进入浏览器产物，不是服务端秘密。
- `AMAP_WEB_SERVICE_KEY`：仅 POI 地理编码需要，普通 UI 开发不需要。不要公开、打印或加 `NEXT_PUBLIC_` 前缀。
- GitHub Actions secrets 不等于 Cloud 环境变量；不能假设自动继承。
- `node_modules/`、`.next/`、`out/` 需要在云端重新生成。
- 本地个人 Skills、插件、聊天记录和浏览器登录状态不随仓库自动迁移。本文件只是可提交的工作交接，不是完整聊天备份。
- 当前官方 Cloud 环境说明列出浏览器/电脑操作尚不支持。不要承诺在 Cloud 中直接使用本机小红书已登录会话；无法操作时记录阻塞，继续可离线处理的开发。
