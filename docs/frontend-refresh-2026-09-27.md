# TraumaCompass 前端优化与指令审查

日期：2026-09-27。范围：现有 Next.js 静态网站的视觉、信息层级、响应式与交互；不扩展采集、地理编码或医疗数据功能。

## 先行指令审查

依据：[OpenAI — Rethinking skills and prompts for GPT-6 Astra](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra)。本次将流程约束限定在任务需要的范围，避免将每个建议变成固定关卡。

| 设置 | 风险 / 原因 | 最小修改建议 |
| --- | --- | --- |
| 任意不确定都停下询问 | 已授权 UI 工作也会反复等待，轻微视觉判断被当成阻塞 | 仅在影响目标、授权、数据安全或难以回退时询问；其余说明假设后继续 |
| 所有修复先写复现测试、循环到验证 | 文案与间距也套用同一流程，容易无界迭代 | 按风险选择类型检查、构建、浏览器交互或自动测试，并预先限定验收点 |
| 禁止相邻改善 / 重构 | 若不识别本次“整体优化”授权，会与用户目标冲突 | 保留默认小范围修改；显式整体改版时允许重整相关 CSS 与组件，不动业务数据 |
| Product Design 新项目模板及多方案关卡 | 对已有代码、品牌与明确诉求的项目重复启动设计流程 | 已有项目走“截图审查 → 选定方向 → 实现 → 对照验收”分支 |
| 审查结束再次请求实施或分享许可 | 用户已经授权优化和 push，再询问造成等待 | 复用当前任务授权；发布到其他服务或扩大范围时再确认 |
| skill 安装固定要求提权联网 | 不匹配当前允许联网、无需审批的环境 | 仅在实际受限时提出必要权限需求 |
| 历史文档保留问号、文案或“本轮禁止提交” | 历史状态误当永久规范，会覆盖最新用户决定 | 当前用户指示优先；把临时审批状态写入任务记录而非长期编辑指南 |
| Next.js 自动生成规则 | 删除后开发服务器会重建；“阅读相关指南”不等于阅读全部文档 | 保留生成块，按当前修改阅读相关本地文档 |

以上为最小建议，未擅改全局 AGENTS 或已安装插件规则。项目编辑指南仅修正失效组件定位与临时禁推说明。开发服务器生成的根目录 AGENTS.md / CLAUDE.md 留在本地，不混入 UI 提交。

## 设计与实现

1. 保留青色丝带品牌，以白色卡片、浅薄荷背景、深青文字统一视觉；统一间距、圆角、边框、图标、焦点轮廓和主要控件点击面积。
2. 地图侧栏宽 380px，品牌与 logo 居中对齐；统计独立三列、标签分段呈现。窄面板筛选默认收起，优先展示机构，同时显示已选条件数量。
3. 机构卡片依次呈现地区、名称、科室、证据、来源与查看入口。空结果可一键清除筛选；全局搜索有清除按钮和无结果反馈。
4. 手机首屏地图优先，底部提供浏览入口；抽屉保留搜索，背景地图 inert，支持标签方向键、Tab 循环与 Escape。取消 visibility 过渡，避免初始焦点丢失。
5. 机构、线索、医生、投稿页面使用一致页头与内容宽度；医生线索优先，尚未收录的结构化执业信息收进独立折叠区，仍保留两类依据的区别。
6. 关于页继续只保留 logo 和标题，不补写用户此前删除的正文；页脚保持 `© 2026 TraumaCompass. All rights reserved.`。
7. 修复全国视图重复预留侧栏宽度的问题；保留 34 个省份标签和白色无数据省份，不恢复问号。省名不再成为空的键盘焦点。
8. GSAP 仅在面板内容上做 220ms、8px 的轻量过渡；不操作 Leaflet 的瓦片、图钉或地图 transform。保留已有整数缩放及动画结束再更新聚合的机制。
